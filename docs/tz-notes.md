# Конспект аналізу технічного завдання проєкту "Student Assistant"

## Функціональні вимоги
- Перегляд переліку завдань.
- Додавання нового завдання (назва, дедлайн, пріоритет).
- Позначення завдання виконаним / невиконаним.
- Редагування та видалення завдань.
- Фільтрація або сортування завдань за станом виконання чи пріоритетом.

## Нефункціональні вимоги
- Кросплатформність: підтримка Windows, macOS, Linux.
- Використання відповідних архітектурних підходів для кожного клієнта (WebView, AOT, віртуальна машина).
- Ведення історії змін виключно через Git і GitHub за моделлю GitHub Flow (гілки, Pull Requests).

## Модулі та технології
| Модуль | Технологія / Фреймворк | Тема курсу |
| :--- | :--- | :--- |
| Веб-клієнт | React | Тема 2 |
| Десктопний контейнер | Electron / NW.js | Тема 3 |
| Нативний десктоп-клієнт | C++ / Qt | Тема 4 |
| Аналітичний модуль | Python / Flet | Тема 4 |

## Формат обміну даними
Усі модулі працюють із єдиним файлом `data/tasks.json`. 
Структура об'єкта завдання:
- `id` (number) — унікальний ідентифікатор.
- `title` (string) — назва завдання.
- `completed` (boolean) — стан виконання (true/false).
- `dueDate` (string) — дедлайн у форматі YYYY-MM-DD.
- `priority` (string) — пріоритет ("low", "medium", "high").

## Відкриті питання
- Яким чином вирішуватиметься конфлікт одночасного запису у файл `data/tasks.json` кількома клієнтами?
- Чи потрібна валідація даних на стороні кожного клієнта перед збереженням JSON?
## Порівняння підходів до стилізації (ПР № 6)

* **Звичайний CSS (App.css):** Легший у розумінні для початківців, відокремлює стиль від логіки компонента. Зручно використовувати для глобальних стилів.
* **Styled Components:** Дозволяє писати CSS прямо всередині JS-файлу та легко передавати props (наприклад, `$priority`) для динамічної зміни кольорів без створення багатьох класів. Усуває конфлікти імен класів у великих проєктах.
